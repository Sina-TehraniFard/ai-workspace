# 文書の書き方

設計判断の一覧、実装計画書、ai-docs の記録、ユーザーへの質問はこのルールで書く。質問は、末尾の「チャットの本文で聞くとき」の形にもする。書き終えたら、このルールに照らして読み直してから出す。

1. 決まったことだけを書く。誰に言われたか、どの会話で決まったかといった経緯は書かない
2. 1つの事柄は1回だけ書く。同じ内容を、表と文章や、肯定と否定の両方の形で繰り返さない
3. 前の文をまとめ直す文を足さない。「つまり」「要するに」で始めたくなったら、どちらか一方の文を残す
4. 括弧は補足のためだけに使う。直前の語を言い換えるだけの括弧は消す
   - 消す: `キャッシュ（一時的に保存したデータ）を使う`
   - 残す: `再試行は3回まで（初回を含まない）`
5. 書くことが無い見出しや行は、まるごと消す。「なし」とだけ書いて残さない
6. 読み手が初めて見る言葉を使わない
   - 助詞を抜いて名詞を詰めた語を作らず、文で書く
   - たとえを使わず、何をするかをそのまま書く
   - 1つの文で言うことは1つにする
7. 表のセルでは場合分けをしない。結果が分かれるなら行を分ける

## チャットの本文で聞くとき

ユーザーに判断を求めるときは、この形で書いてターンを終える。

1. 先に、判断に要る事実を箇条書きで並べる。各行に根拠のファイル・行番号・コマンド結果を添える
2. 質問は最後にまとめ、番号を振る。1回に聞くのは、次に進むのに要る分だけにする
3. 選択肢は、質問の下に `- a.` `- b.` の形で並べる。ユーザーが記号だけで答えられるようにする
4. 各選択肢の後の括弧に、選んだ後に何をするかを書く
5. 推奨する選択肢は先頭に置き、括弧の頭に `推奨。` と書く

```
1. このタスクをいつ始めますか？
   - a. 今すぐ始める（推奨。状態は「進行中」にして、要件の把握から進めます）
   - b. 後で始める（状態は「着手予定」にして、フォルダを作るところまでで止めます）
```
